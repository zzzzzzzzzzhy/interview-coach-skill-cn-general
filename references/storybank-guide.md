# Storybank Guide

本文件定义 `Storybank` 的使用方法。`Storybank` 是经历故事库，用于行为面、自我介绍、简历证明、pitch 和面试追问。

协议名、表头、ID 保持英文；故事正文可以中文。

## Storybank Index

保存在 `coaching_state.md` 的 `## Storybank`：

| ID | Title | Primary Skill | Secondary Skill | Earned Secret | Strength | Use Count | Last Used |
|---|---|---|---|---|---|---|---|

规则：

- ID 使用 `S001`、`S002`。
- Strength 1-5。
- Use Count 记录真实面试使用次数。
- Last Used 记录最后一次真实使用日期。

## Story Details

每个故事必须写入 `### Story Details`：

```markdown
#### S001 — [Title]
- Situation:
- Task:
- Action:
- Result:
- Earned Secret:
- Deploy for:
- Version history:
```

不要只保存表格索引。没有完整 Story Details，后续无法复用和改进。

## Good Story Standard

强故事包含：

- 明确背景。
- 真实冲突或难点。
- 候选人个人动作。
- 可验证结果。
- 反思或取舍。
- 对目标岗位有用的能力信号。

## Story Strength

| Strength | Meaning |
|---|---|
| 1 | 太薄，不能直接用 |
| 2 | 有素材但证据不足 |
| 3 | 可用，但普通 |
| 4 | 强故事，能支撑多数面试 |
| 5 | 标志性故事，高压追问下也站得住 |

## Skill Tags

常见 Primary / Secondary Skill：

- leadership
- ownership
- collaboration
- conflict
- ambiguity
- problem solving
- technical depth
- product judgment
- data analysis
- execution
- communication

可按行业新增中文说明，但表格字段保持英文。

## Story Discovery Prompts

一次只问一个：

- 哪件事最能证明你解决过真实问题？
- 哪件事让你从不会到会？
- 哪件事最难，但最后你扛住了？
- 哪次你做了一个取舍？
- 哪次别人对你的工作有明确反馈？
- 哪个项目如果没有你，结果会明显不同？

## Rapid-Retrieval Drill

用于 `stories drill` 或 `practice retrieval`：

1. 连续给 10 个问题。
2. 候选人 10 秒内回答故事 ID + 开场句。
3. 记录卡壳、错配、重复使用。
4. 更新 Storybank 和 Drill Progression。

## Rules

- 不编造故事。
- 不把团队贡献全部说成个人贡献。
- 每个故事至少准备 30 秒、90 秒版本。
- 已经在同家公司前几轮用过的故事，要注意 freshness risk。
