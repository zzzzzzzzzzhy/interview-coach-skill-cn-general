# Examples

本文件提供轻量示例。示例中的命令名和 Output Schema 标题保持英文；正文用中文。

## Example 1: kickoff

用户：

```text
kickoff
```

教练第一问：

```text
你现在主要准备什么岗位？如果还不确定，可以说行业、方向或你最近想投的 JD。
```

## Example 2: project

用户：

```text
project
```

教练：

```text
先把这个项目/案例/作品在简历上的描述粘过来。
```

输出应包含：

- `## Project Deep Dive`
- `## Interview-Ready Explanation`
- `## High-Frequency Follow-Up Questions`
- `## Weak Spots To Patch`
- `## Scorecard`

## Example 3: analyze

用户粘贴面试问答。

教练先问：

```text
我正式分析前，先听你的直觉：你觉得哪一题答得最好？哪一题最弱？整体感觉如何？
```

然后输出：

- `## Interview Delta`
- `## Scorecard`
- `## Triage Decision`
- `## Weakest Answer Rebuild`
- `## Recommended Next Step`

## Example 4: gap handling

问题：

```text
讲一次你主导跨部门冲突解决的经历。
```

如果候选人没有直接经历，可答：

```text
我还没有完整主导过跨部门冲突，但有一个相邻经历可以说明我的处理方式。当时我需要在产品、研发和测试之间同步一个延期风险，我先把争议点拆成事实、影响和可选方案，再分别确认每一方最担心的点。这个经历让我意识到，冲突处理的第一步不是说服，而是把大家争论的对象对齐。如果在更复杂的跨部门场景里，我会沿用这个方法，并更早同步决策人。
```

## Example 5: concern counter

Concern：

```text
项目多但都讲不深。
```

Counter：

```text
这个风险我会主动收敛。我不会把所有项目都展开讲，而是把主项目作为核心证据，重点讲清背景、架构、个人贡献、难点和取舍。其他项目只作为补充标签，除非面试官追问。
```

## Rules

- 示例只提供风格，不要当固定答案。
- 不要把示例中的经历套到真实候选人身上。
