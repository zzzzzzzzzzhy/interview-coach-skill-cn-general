# Detailed Scoring Rubrics

本文件定义详细评分标准。维度名保留英文，解释和反馈用中文。

## Core Rubric

五个通用维度，每项 1-5 分：

- Substance：内容质量、证据和深度。
- Structure：叙事结构和表达清晰度。
- Relevance：是否命中问题和岗位要求。
- Credibility：真实性、个人贡献和可信证据。
- Differentiation：是否有辨识度，是否只有这个候选人能这样回答。

## Substance

| Score | Description |
|---|---|
| 1 | 空泛口号，没有证据 |
| 2 | 有主张但支撑很弱 |
| 3 | 有具体事件，但缺少结果、指标或取舍 |
| 4 | 有结果和上下文，但还缺备选方案或决策理由 |
| 5 | 有事实、指标、约束、取舍、个人贡献和结果验证 |

常见根因：

- 没复盘过真实细节。
- 回避冲突和困难，导致故事没有张力。
- 不敢讲自己的贡献。
- 只讲做了什么，不讲为什么和结果。

## Structure

| Score | Description |
|---|---|
| 1 | 想到哪说到哪，听者跟不上 |
| 2 | 有内容但主线很晚才出现 |
| 3 | 有基本 STAR，但转折生硬或背景过多 |
| 4 | 结构清楚，少量冗余 |
| 5 | 结论先行，逻辑顺滑，每句话都服务主线 |

常见根因：

- 细节囤积，怕漏信息。
- 没有 30/60/90 秒版本。
- 紧张导致结构崩。

## Relevance

| Score | Description |
|---|---|
| 1 | 没回答问题 |
| 2 | 主题相关但核心没答 |
| 3 | 回答了问题，但夹杂大量无关内容 |
| 4 | 直接回答，有少量偏移 |
| 5 | 高度聚焦，所有内容都服务问题 |

常见根因：

- 不会判断问题真正考点。
- 先想“我要讲哪个故事”，而不是先想“对方问什么”。
- 喜欢套熟悉素材。

## Credibility

| Score | Description |
|---|---|
| 1 | 明显夸大或没有支撑 |
| 2 | 支撑模糊，个人贡献不清 |
| 3 | 有细节，但缺结果或验证 |
| 4 | 可信，有指标和约束，但证明链还可更强 |
| 5 | 个人动作、结果、第三方反馈、约束和边界都清楚 |

常见根因：

- “我们”太多，“我”太少。
- 为弥补背景焦虑而过度包装。
- 写了自己讲不清的内容。

## Differentiation

| Score | Description |
|---|---|
| 1 | 完全模板化，任何人都能说 |
| 2 | 有一点具体，但还是常见框架 |
| 3 | 真实但不独特 |
| 4 | 有 earned secret 或明确个人判断 |
| 5 | 有独特经验、可辩护观点和清晰方法论，很难被替代 |

常见根因：

- 只背最佳实践。
- 怕表达立场。
- 没从经历里提炼自己的判断。

## Technical / Campus Rubric

技术岗、校招技术面可使用：

- Technical Accuracy
- Project Depth
- Personal Contribution
- Expression Structure
- JD Match

| Score | Description |
|---|---|
| 1 | 概念错误或无法解释 |
| 2 | 能说表层，但经不起追问 |
| 3 | 基本正确，有实现细节但缺边界和取舍 |
| 4 | 能讲清原理、实现、问题和选择理由 |
| 5 | 能讲清机制、替代方案、生产风险、指标和个人贡献 |

## HR Rubric

- Motivation Authenticity
- Stability
- Communication Maturity
- Pressure / Review Ability
- Expectation Fit

强回答要真实、稳定、有证据，不要只说套话。

## Root Cause Taxonomy

| Root Cause | How It Shows Up | Fix |
|---|---|---|
| Inability to identify question core | 答非所问 | 先复述问题考点，再选故事 |
| Reflexive "we" framing | 个人贡献不清 | 做 I/we audit |
| Conflict avoidance | 故事没有难点 | 挖最难一刻 |
| Status anxiety / over-claiming | 过度包装，可信度下降 | 加约束、边界、真实贡献 |
| Narrative hoarding | 回答过长，结构松 | 30/60/90 秒压缩训练 |
| Fear of being wrong | 回答安全但没记忆点 | 练 spiky POV |
| Anxiety / performance stress | 卡壳、跑题、崩结构 | 做 hype 和恢复脚本 |
| Cultural / linguistic adaptation | 表达风格和面试期待不匹配 | 做适配，不否定候选人原风格 |

## Seniority Calibration

- Early career：看学习速度、具体执行、基础扎实、反思。
- Mid-career：看独立负责、结果、取舍、跨团队协作。
- Senior / lead：看影响范围、判断质量、带人/推动、复杂问题处理。
- Executive：看战略、组织影响、资源配置和风险承担。

评分时必须说明使用哪个 calibration band。

## Rules

- 分数必须有证据。
- 不要为了鼓励虚高打分。
- 多个维度低时，先解决上游问题：Relevance -> Substance -> Structure -> Credibility -> Differentiation。
- 用户可见反馈用中文，但维度名保留英文以保持状态一致。
