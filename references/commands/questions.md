# questions — Questions To Ask Workflow

本文件用于 `questions` 命令。目标是准备面试最后反问，而不是凑几个礼貌问题。好的反问应该帮候选人获取信息、展示思考深度、降低疑虑，或者建立连接。

中文化规则：命令名、状态章节名、Output Schema 标题保持英文；问题内容和解释使用中文。

## Logic

先读取 `coaching_state.md`。如果有公司、岗位、JD、面试轮次或面试官信息，问题必须针对这些上下文。

如果上下文不足，第一问：

“这几个反问是给哪一轮用的：HR/电话初筛、业务面/用人经理、终面、同事面，还是技术/专业面？”

## Strategic Purposes

每个问题至少服务一个目的：

- information：了解岗位、团队、流程或期望。
- concern mitigation：间接展示候选人的优势，缓解某个顾虑。
- differentiation：体现思考深度，让候选人更有记忆点。
- rapport：和面试官角色、背景或关注点建立连接。

## Stage Adaptation

- Phone screen / recruiter call：问流程、岗位范围、评价标准，不问过深战略问题。
- Hiring manager round：问团队目标、挑战、成功标准、协作方式。
- Peer round：问日常协作、真实工作方式、入职体验。
- Final round / exec：问组织方向、战略重点、长期机会。
- Technical / specialist round：问技术决策、质量标准、系统演进、专业挑战。
- Portfolio / presentation round：问评审标准、业务约束、后续落地。

## Questions To Avoid

提醒候选人避开：

- 官网/JD 一眼能查到的问题。
- 太早问福利、假期、摸鱼空间。
- 暴露不自信的问题，如“你觉得我够格吗？”
- 过于泛的问题，如“公司文化怎么样？”
- 让对方难堪的问题，如“这里最糟糕的地方是什么？”

## Coaching State Integration

如果是公司特定面试，把 top 3 反问写入：

`## Interview Loops (active)` -> 对应公司 -> `Prepared questions`

这样 `hype` 可以复用已有问题，避免重复生成互相矛盾的反问。

## Rules

- 每个问题必须适配轮次和面试官类型。
- 不要给“万能但空”的反问。
- 反问后要准备对方反问回来时怎么接。
- 如果用户想要强势风格，也要保持礼貌和职业边界。
